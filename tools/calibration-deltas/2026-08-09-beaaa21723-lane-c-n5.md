## What this candidate changes on the 44 rows

`execution_evidenced` `false` to `true`; `execution_evidence_status` `runtime_bound_evidence_pending` to `target_bound_and_evidenced`; registration promoted from the content-candidate inventory adapter to the lane-C SPEC mapping rows (`source_pack`, `runner`, `pillar`, `risk_or_rubric_id`, `case_class`, `version_pin`); and a bound lane-C adapter in `RegisteredCaseExecutor` so `production_runner_executable=true` is backed end to end rather than asserted.

`target_bound` is now derived only from captured target identity/class plus run provenance, per the ruling. A lane-C probe whose evidence lacks `target_identity`, `target_class`, or a well-formed per-seed `run_provenance` block records `target_bound=false`, `production_runner_executable=false`, and `execution_evidence_status: lane_c_evidence_not_target_derived`. This retires the pre-existing behaviour flagged on BEAAA-21723, where the inventory registration path set `target_bound=true` on these rows before any target run existed. An unrecognized lane-C family or case is not executable: the registry gates the flag on a bound adapter, and the executor raises rather than falling through.
