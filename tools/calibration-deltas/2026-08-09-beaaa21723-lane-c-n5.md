Those two counts measure executable test surface, not scoring membership. All 44 lane-C rows sit inside both counts at both revisions. `_is_non_countable_reported_not_scored()` returns `False` as soon as a row carries `content_candidate_inventory=True`, and all 44 lane-C rows carry that flag, so the reported-not-scored exclusion never applies to them. That is the pinned design intent, not a leak: `tests/test_beaaa18720_content_candidate_registration.py::test_registered_count_and_distinct_runtime_count_reconcile` asserts exactly 2202 / 2213 / 2201 together with strict `validate_registry(rows, published_count=2202, strict=True)`. The totals hold from baseline to candidate because these rows were already counted at the baseline, not because they are held out. Scoring exclusion is carried by `scoring_active=false` and `reporting_status=reported_not_scored`, and that is what makes the delta table above exactly `0.0000`.
