## What the change does

The BEAAA-23968 shape applied verbatim. Both runners take `corpus_yaml` defaulting to their own map through a module-level `DEFAULT_CORPUS_YAML`, and derive `corpus_version`, `probe_set_version`, and `benchmark` from it via `corpus_pin.load_probe_set_version` and `corpus_pin.benchmark_label`. Explicit `corpus_version` and `probe_set_version` arguments still win, so replay against an archived corpus keeps working. The shape fit both families without variation: same envelope layout, same keyword-only signature, same `reproducibility.probe_set_version` key in both YAMLs. No new module, no new design decision.

The two `scripts/beaaa8127_ops_live_fire.py` call sites that passed the literals now pass `corpus_yaml=mapping_paths["P1.3"]` and `mapping_paths["P1.5"]`, the same paths they load the probes from, so the label and the roster cannot come from different files. Those were the only production call sites passing pins; the P1.3 and P1.5 test suites already ran on defaults.

`corpus_pin.py` itself changes by one docstring paragraph recording that all four golden families now route through it.
