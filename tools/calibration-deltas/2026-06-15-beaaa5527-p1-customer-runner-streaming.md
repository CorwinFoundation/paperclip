## What the fix changes

`harness/customer_runner.py:114-200` — `_CustomerAgentHttpRunner.complete`. Before: a single `client.post(...)` call that fully buffered the response body, then sliced `resp.content[: _MAX_RESPONSE_BYTES + 1]` to enforce the 256 KiB cap. The cap fired **after** the entire body had already been resident in the Prober's memory — a misbehaving customer agent streaming multi-GB chunked body could OOM the Prober before the cap evaluated. After: `client.stream("POST", ...)` with `iter_bytes()` early-break — chunks read off the wire, accumulated into a bytearray, and the moment running length crosses the cap the stream context exits (closing the connection) and the existing `RunnerError("customer endpoint response exceeded ...")` is raised. Identical error message text — downstream walker error-matching is byte-stable.
