# ADR-0036: BackBond Scanner v0.5 RC Cut

## Decision

Cut BackBond Scanner `0.5.0` as the v0.5 release candidate with `rubric/rubric.yaml` held at `1.2.0` and `contracts/are-scanner-api-v1.md` held at `are-scanner-api-v1@v1.3.0`.

## Classification

Rule-change release cut under `contracts/scanner-implementation-supervision-v1.md@v1.1`.

Rows applied:

- Contract/version release cut with CTO + Underwriter co-sign before merge.
- No new rubric point, retired rubric point, pillar-weight change, scoring-math change, judge-model change, or tamper-resistance posture reduction in this RC branch.

## Reasoning

BEAAA-6188 codified the 40-point discrimination spread floor as a CI release gate. It did not add a rubric-side scoring gate, so `rubric/rubric.yaml` remains `1.2.0`.

BEAAA-6187 added customer-VPC evidence custody via feature-flagged `BACKBOND_EMIT_MODE=customer_vpc`. Default score-output field shape remains unchanged, so `contracts/are-scanner-api-v1.md` remains `are-scanner-api-v1@v1.3.0`.

BEAAA-7340 repointed M6 from the external pen-test report gate to the completed internal red-team gate, BEAAA-7321. External pen-test tracking remains on BEAAA-6186/BEAAA-6199 as future hardening and is not a v0.5 RC blocker.

## Version Disposition

| Surface | Prior | Candidate | Reason |
|---|---:|---:|---|
| `scanners.SCANNER_VERSION` | `0.4.2` | `0.5.0` | RC build stamp for M6. |
| `rubric/rubric.yaml` | `1.2.0` | `1.2.0` | M2 spread floor is CI-side, not rubric-side. |
| `contracts/are-scanner-api-v1.md` | `v1.3.0` | `v1.3.0` | M3 customer-VPC URI projection is feature-flagged custody, not a default output-shape change. |
| `CONTRACT_VERSION` | `are-scanner-api-v1@v1.3.0` | `are-scanner-api-v1@v1.3.0` | Parity with contract frontmatter retained. |

## Calibration Delta

Calibration artifact: `tools/calibration-deltas/2026-06-22-beaaa6190-v05-rc-n5.md`.

Expected gate:

- N=5 on every live golden fixture must be byte-identical to its locked `expected_score.json`.
- Total and every pillar spread must be `0`, which is stricter than the ±1 release band.
- Live-golden discrimination spread must be at least `40` BackBond Score points.
- Pending roster slots remain explicit `pending_baseline_scan` entries, not silently dropped from inventory.

## Rejected Alternatives

1. **Force `rubric/rubric.yaml` to `1.3.0`.** Rejected. That would imply a rubric-side rule change that BEAAA-6188 did not ship.
2. **Force contract `v1.4.0`.** Rejected. BEAAA-6187 closeout states no default score-output field shape changed.
3. **Keep scanner stamp at `0.4.2`.** Rejected. M6 is a release cut; downstream evidence needs a distinct build stamp.

## Rollback

Tier 1 rollback:

1. Revert `scanners.SCANNER_VERSION` from `0.5.0` to `0.4.2`.
2. Revert golden expected-score metadata stamps from `0.5.0` to `0.4.2`.
3. Remove the BEAAA-6190 RC workflow/script/artifacts.
4. Retag the prior scanner build as the active pre-RC candidate.

No data migration is required because no contract output shape, scoring math, rubric weights, or judge models changed.
