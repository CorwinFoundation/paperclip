# Findings evidence after a case recovery

A report may use a later complete response for a previously unavailable case only
as an explicit recovery overlay. The original Scanner result, source inventory,
selection and successful grades remain unchanged. This overlay does not run a
target, grant permission for a call, change entitlement, regrade an existing
response or approve a report.

The initial supported scope is the anonymous Pollinations JSON mapping transport,
`starter-100@4`, with a separately authorized `reasoning_effort: low` recovery.
There is no default request-setting change and no automatic recovery call.

The authenticated intake producer verifies the immutable Scanner result and saved
form, matches all original successful inputs, and retains exact request/response
records privately. It obtains the first ordinary Starter grade for each complete
new reply. A new immutable workflow request contains `capture_recovery` with the
original source rows, their digest, the unchanged selection digest, the original
result digest, authorization reference, prior failed attempts, complete recovery
lineage, exact request bytes and first-grade bindings. Include every known failed
attempt, if any; extra failed diagnostic calls are not a prerequisite. Retained
HTTP error bodies carry their private file digest. A historical capture gap is
disclosed instead of being required for future recoveries.

Validation requires all 100 selected identities, exact preservation of every
successful original row, one complete recovery per original unavailable identity,
matching prompt/reply/request hashes, provider termination `stop`, the supported
request settings, ordered observation times and matching first-grade hashes. A
partial reply, cleared original unavailable list, replacement of an earlier grade,
changed model or arbitrary request parameter refuses admission. Ordinary requests
still require no unavailable selected cases. Adjudication and capture recovery
cannot be combined in one request.

The evidence archive includes the original capture inventory, unchanged selection
and recovery overlay. It identifies the effective evidence as recovered and not
uniformly configured. Writer and independent Reviewer must disclose original and
recovered counts and the setting change beside the coverage statement. An
aggregate BackBond Score is N/A. Recorded outcome counts do not establish a rating
for one uniform configuration. Missing system-prompt or owner facts still limit
the claims a finding can make.

All existing native role, parentage, review, artifact-hash and mechanical release
checks remain required. Only genuine independent approval permits the normal
service to email the authenticated report link to `info@backbond.ai`. No manual
email, extra delivery card, CI-routing change or paid fallback is introduced.
