# are-scanner PRODUCTION RUNTIME dependency contract — the online-service slice.
# BEAAA-13329 (rule-execution of ADR-0038, decisions/ADR-0038-runtime-requirements-slice.md).
#
# WHAT THIS IS
# ------------
# This is the dependency set the *live* production service actually imports:
# the FastAPI app (api/*) and the live customer-scan chain
# (scanners.live_probe_orchestrator/workers, score_runtime,
# customer_agent_walker, harness.runner/customer_runner/credentials/egress).
# The production venv (deploy/cto_live_edge_boot.py under uvicorn) is built
# from THIS file, not from requirements.txt.
#
# WHY THIS EXISTS (structural, not incidental)
# --------------------------------------------
# requirements.txt is the full eval-framework RELEASE-CONTRACT superset and is
# NOT co-installable in one venv by design: garak==0.10.0 requires
# datasets<2.17 while pyrit==0.6.0 requires datasets>=3.0.0 (garak ⊥ pyrit).
# Both frameworks — plus agentdojo and inspect-ai — are OFFLINE-ONLY: they are
# imported solely by scanners/{pyrit,agentdojo,inspect}_runner.py, each of
# which soft-imports (try/except ImportError -> _AVAILABLE=False). garak is
# never imported in Python at all (driven via the promptfoo Node CLI). None
# of the four are in the live runtime import closure, so excluding them from
# the production venv cannot move a live score and cannot crash the service.
# See requirements-scanner-regression.txt for the same conflict noted on the
# CI regression slice, and ADR-0038 for the full import-closure analysis.
#
# INVARIANT (enforced by CI): this file must stay a true SUPERSET of the live
# import closure. tests/test_runtime_import_closure_beaaa13329.py builds a venv
# from this file only, imports the live modules, and asserts the four eval
# frameworks are NOT importable. If a live dependency is missing here, that
# test fails — add the dep here (never re-add garak/pyrit/agentdojo/inspect-ai).
#
# Scoring / rubric / corpus / judges are UNCHANGED relative to requirements.txt;
# this is a packaging change only.
